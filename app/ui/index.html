How a request flows

  1. Auth API key → user, checked against a SHA-256 hash
  2. Rate limit token bucket in Redis (Lua, atomic)
  3. Decode real format check, pixels, SHA-256 of the bytes
  4. Cache Redis lookup on task : model version : hash
  5. Store image saved once per user in S3 storage + Postgres row
  6. Queue waits up to 10 ms for other requests to share a batch
  7. GPU one Florence-2 forward pass for the whole batch
  8. Save cache write + request row in Postgres

Analyze an image to see these stages timed for your request.

Watch dynamic batching happen

Fire many requests at the same moment. Each one is your image with a single pixel changed, so its SHA-256 is new and it misses the cache. The server's batcher collects up to 8 waiting requests (or waits 10 ms) and runs them through the GPU together. Requests that share a GPU pass line up below.
